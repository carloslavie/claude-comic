## Idioma

Responder siempre al usuario en español en este proyecto.

## Proyecto

**PictureFactory**: una aplicación web con varias herramientas para trabajar con fotos. Abre en un menú inicial desde el que se elige la herramienta. Hay tres disponibles: el creador de comics, que carga imágenes y las acomoda automáticamente como páginas de un libro de historietas; el de cuadros, que recorta cada foto a la medida de un marco (con paspartú opcional y reencuadre a mano) y genera un PDF a tamaño real con marcas de corte (las medidas A4 y A3 salen una por hoja, borde a borde); y el de stickers, que recorta cada foto con una forma (círculo, cuadrado, cuadrado redondeado o rectángulo 3:2 horizontal o vertical, recto o redondeado), con borde opcional, reencuadre a mano y copias por foto, y genera un PDF a tamaño real con una línea de corte sobre el contorno de cada sticker.

Corre entera en el navegador: las imágenes nunca salen de la máquina y no hay backend.

## Stack y comandos

Vite + JavaScript sin framework (ES modules). Vitest para los tests unitarios. jsPDF para generar el PDF. Las fuentes del título (Bangers, Luckiest Guy, Permanent Marker, Anton, Kosugi Maru, M PLUS Rounded 1c y Dela Gothic One) vienen de `@fontsource` y se empaquetan con la app, sin pedidos externos. No hay configuración de lint.

- `npm run dev`: servidor de desarrollo.
- `npm test`: ejecuta los tests una vez (`vitest run`). Para un solo archivo: `npx vitest run tests/layout.test.js`.
- `npm run build`: build de producción en `dist/`. `npm run preview` lo sirve.

Los tests cubren solo la lógica pura (`orientation.js`, `layout.js`, `colors.js`, `titleStyle.js`, `pdfFormat.js`, `tools.js`, `frameSizes.js`, `crop.js`, `sheetLayout.js` y `stickerSizes.js`). La UI, el menú, el render en canvas y los PDF se verifican a mano (ver los criterios de aceptación de `specs/01-mvp-comic-pdf.md`, `specs/08-cuadros-una-foto.md`, `specs/09-cuadros-hoja-completa.md`, `specs/10-stickers-hojas.md` y `specs/11-stickers-rectangulares.md`).

## Arquitectura

Navegación: `index.html` tiene una vista por pantalla, cada una con `data-view="<view>"`: el menú (`<section data-view="home">`), el comic (`<div id="comic-view" data-view="comic">`), los cuadros (`<div id="frames-view" data-view="cuadros">`) y los stickers (`<div id="stickers-view" data-view="stickers">`). Las vistas se muestran y se ocultan con el atributo `hidden` y nunca se destruyen. La ruta sale del hash: `#/` o sin hash es el menú, `#/comic` es el comic, `#/cuadros` son los cuadros y `#/stickers` son los stickers. Cualquier otro hash (o el de una herramienta no disponible) se reemplaza por `#/` con `history.replaceState`. `initUI()`, `initFramesUI()` e `initStickersUI()` se llaman una sola vez al arrancar, aunque se entre por el menú, así que el trabajo de cada herramienta se conserva en memoria entre vistas. Una regla CSS con `display` en una vista le gana a `hidden`, así que necesita su propia regla `[hidden] { display: none; }` (como `#comic-view[hidden]`).

Flujo de datos del comic: `state.images` (+ `state.pageTemplateOverrides`) → `buildPages()` → `renderPage()` por página, en un canvas. El color de fondo de cada página se resuelve con `resolvePageColor()` y se le pasa a `renderPage()`, junto con `state.titleStyle`. La vista previa y el PDF usan el mismo render, así que lo que se ve es lo que se exporta.

Flujo de datos de los cuadros: `frameState.images` + la medida, el paspartú y la hoja → `frameFor()` por foto → `renderFrame()` en un canvas. La vista previa (una tarjeta por foto) y el PDF usan el mismo render; el PDF además acomoda los cuadros con `packFrames()`.

Flujo de datos de los stickers: `stickerState.images` + la forma, el tamaño, el borde y la hoja → `stickerFor()` (el sticker en `width` × `height` mm) → `renderSticker()` en un canvas. La vista previa (una tarjeta por foto) y el PDF usan el mismo render; el PDF repite cada foto según sus `copies` con `expandCopies()` y las acomoda con `packFrames()`.

- `src/main.js`: punto de entrada; carga las fuentes de `@fontsource` y los estilos, y llama a `initUI()`, `initFramesUI()`, `initStickersUI()` y después a `initHome()`.
- `src/tools.js`: herramientas del menú y reglas de navegación, lógica pura. `APP_NAME` (`PictureFactory`) y `TOOLS` (`comic`, `cuadros`, `stickers`, cada una con `title`, `description`, `tabTitle` y `available`; el orden de inserción es el orden de las tarjetas). `toolHash(id)` → `#/<id>`. `resolveRoute(hash)` → `{ view, hash }`: `view` es `home` o el id de una herramienta disponible y `hash` es el que tiene que quedar en la URL. `documentTitle(view)` → `PictureFactory` o `<tabTitle> · PictureFactory`. Habilitar una herramienta es poner `available: true` y agregar su vista.
- `src/home.js`: `initHome()` arma las tarjetas del menú en `#tool-list` desde `TOOLS`, con íconos SVG en línea definidos por id de herramienta. La tarjeta disponible es `<a class="tool-card">`. Las no disponibles son `<div class="tool-card is-soon" aria-disabled="true">`, sin `href` ni `tabindex`, con la etiqueta "Próximamente" (hoy no queda ninguna, pero el soporte se conserva). Aplica la ruta al arrancar y en cada `hashchange`: corrige el hash, muestra la vista, muestra el enlace "← Inicio" (`#home-link`) solo fuera del menú y pone `document.title`.
- `src/state.js`: estado en memoria (`title`, `images`, `pageColor`, `pageColorOverrides`, `pageTemplateOverrides`, `titleStyle`, `pdfFormat`) y sus mutaciones (`addFiles`, `moveImage`, `removeImage`, `setTitle`, `setPageColor`, `setPageColorOverride`, `clearPageColorOverride`, `prunePageColors`, `setPageTemplateOverride`, `clearPageTemplateOverride`, `prunePageTemplates`, `setTitleStyle`, `resetTitleStyle`, `setPdfFormat`). `addFiles` valida el tipo (JPG/PNG/WebP), aplica el límite de 40 y decodifica cada archivo a `ImageBitmap` una sola vez. `pageColorOverrides` guarda el color propio de cada página y `pageTemplateOverrides` la plantilla elegida a mano, ambos por índice de página (0-based, la portada cuenta). `titleStyle` es uno solo para el comic: `setTitleStyle(partial)` cambia solo las opciones que recibe. `setPdfFormat(format)` ignora las claves que no están en `PDF_FORMATS`.
- `src/orientation.js`: `getOrientation(w, h)` → `landscape` (>1.2), `portrait` (<0.83) o `square`.
- `src/colors.js`: `DEFAULT_PAGE_COLOR` (`#ffffff`), `PALETTE` (8 colores), `resolvePageColor(index, pageColor, overrides)` (color propio de la página o el global) y `prunePageColorOverrides(overrides, pageCount)` (descarta los índices de páginas que ya no existen).
- `src/titleStyle.js`: estilo del título de la portada. `DEFAULT_TITLE_STYLE` (`size`, `font`, `position`, `color`, `outlineColor`, `outline`) y los catálogos `TITLE_SIZES` (tamaño máximo en mm: 14 / 22 / 32), `TITLE_FONTS` (pila de fuentes CSS), `TITLE_POSITIONS` y `TITLE_OUTLINES` (grosor como fracción del tamaño de letra). El orden de inserción es el orden del desplegable. `titleBlockTop(position, rectY, rectH, blockH)` es la `y` superior del bloque de texto (arriba y abajo dejan 5 % del alto).
- `src/templates.js`: catálogo fijo de 8 plantillas (`1-full`, `2-rows`, `2-cols`, `3-top-wide`, `3-bottom-wide`, `3-left-tall`, `3-right-tall`, `4-grid`), cada una con un `label` legible para el desplegable. Las viñetas están en fracciones 0..1 del área útil, sin medianil. El orden de `panels` define qué imagen va en cada viñeta (`imageIds[i]` en `panels[i]`). El orden de inserción define el orden dentro de cada grupo del desplegable. `3-bottom-wide` y `3-right-tall` solo se eligen a mano: la regla automática no las usa.
- `src/layout.js`: `buildPages(images, title, templateOverrides = {})`, función pura. Cada página usa la plantilla elegida si entra en las imágenes que quedan; si no, la regla automática según la orientación. Con título, la primera página es la portada (ignora cualquier elección). Cada página trae `layoutMode` (`auto`, `manual` o `fallback` si la elección no entra) y `available` (imágenes que quedan desde ella, incluida). `prunePageTemplateOverrides(overrides, pageCount)` descarta los índices de páginas que ya no existen.
- `src/render.js`: `renderPage(page, imagesById, canvas, title, background, titleStyle = DEFAULT_TITLE_STYLE)`. Toma la escala del ancho del canvas. Pinta el fondo (margen y medianil) con `background`. Aplica margen (10 mm), medianil (4 mm), borde (0.8 mm), recorte cover y el título de la portada. El título usa el tamaño máximo del estilo y se achica hasta 6 mm si no entra; una clave desconocida en `titleStyle` usa el valor por defecto.
- `src/ui.js`: DOM y eventos del comic, dentro de `#comic-view`. Después de cada cambio de estado, `refresh()` redibuja las miniaturas y agenda la vista previa (una vez por frame). Usa `createColorPicker()` para el color global y para el de cada página. Cambiar el color de una página redibuja solo su canvas, sin reconstruir la vista previa, para no cerrar el selector nativo. `createTemplateControl()` arma el desplegable de plantilla de cada página de viñetas ("Automático" + las 8 plantillas, ordenadas por cantidad de viñetas, deshabilitadas si no entran) y el aviso de `fallback`; cambiarlo llama a `refresh()` y reconstruye toda la vista previa, porque reacomoda las páginas siguientes. El `<fieldset id="title-style">` tiene los controles del estilo del título (`renderTitleStyleControls()`: Tamaño, Fuente, Posición, dos selectores de color y Grosor del contorno) y el botón "Restablecer estilo", que los vuelve a armar. El fieldset se deshabilita sin título. `loadTitleFont()` carga la fuente del título con `document.fonts.load`, porque el canvas no espera a las fuentes: se llama al escribir el título, al cambiar de fuente, al restablecer y antes de exportar. El desplegable `#pdf-format`, junto a "Descargar PDF", se arma desde `PDF_FORMATS` y se deshabilita igual que el botón. Cambiarlo solo llama a `setPdfFormat`: la vista previa sigue en A4.
- `src/pdfFormat.js`: formato de hoja del PDF, lógica pura. `DEFAULT_PDF_FORMAT` (`a4`) y `PDF_FORMATS` (`a4`: 1 página por hoja; `a3`: 2 páginas por hoja). `buildSheets(pageCount, format)` reparte las páginas en hojas seguidas (`[[0, 1], [2, null]]` con A3 y 3 páginas); un formato desconocido se trata como A4. `pdfFileName(title, format)` arma `<titulo-kebab>.pdf` o `comic.pdf`, con sufijo `-a3` en A3.
- `src/pdf.js`: `exportPdf(pages, imagesById, title, backgrounds, titleStyle, format = 'a4', blankColor)` dibuja cada página con su color de fondo y la portada con el estilo del título a 1240 × 1754 px (150 DPI) y la agrega como JPEG 0.85 de 210 × 297 mm. Con A4, una página por hoja vertical. Con A3, hojas apaisadas con la página izquierda en `x = 0` y la derecha en `x = 210`; la mitad vacía de la última hoja se pinta con `blankColor` (el color de fondo global). Descarga el archivo con `pdfFileName`.
- `src/colorPicker.js`: `createColorPicker({ value, onChange, label })` arma el selector de color (paleta + `<input type="color">`). Lo usan las tres herramientas.
- `src/messages.js`: `showMessages(container, rejected)` muestra los rechazos de la carga (`type`, `decode`, `limit`) y `showErrors(container, lines)` cualquier lista de errores. Los usan las tres herramientas.
- `src/frameSizes.js`: medidas de cuadro y paspartú, lógica pura, en mm. `FRAME_SIZES` (`10x15`, `13x18`, `15x20`, `20x25`, `20x30`, `a4`, `a3` con `short`/`long`, y `custom`; `a4` y `a3` llevan `fullSheet` con la hoja que ocupan enteras), `DEFAULT_FRAME_SIZE` (`13x18`), `CUSTOM_SIZE_LIMITS` (50..400 mm, lado corto hasta 270), `MATS` (`none`, `fino` 10, `medio` 20, `ancho` 40), `DEFAULT_MAT`, `DEFAULT_MAT_COLOR` y `MIN_PHOTO_MM` (20). `frameOrientation(w, h)` (apaisada → `landscape`, el resto `portrait`), `resolveFrameSize(sizeId, customSize)`, `fullSheetFor(sizeId)` (hoja de una medida de hoja completa o `null`; la personalizada nunca lo es), `frameDimensions(size, orientation)`, `normalizeCustomSize(a, b)` (`{ short, long }` o `null`), `clampCustomSize(size)` (recorta a `CUSTOM_SIZE_LIMITS`), `effectiveMat(matId, w, h)` (se achica para dejar 20 mm de foto) y `photoArea(w, h, mat)`.
- `src/crop.js`: encuadre de una foto, lógica pura. El encuadre es `{ zoom, centerX, centerY }` (zoom 1..3, centro en fracciones 0..1 de la foto; `DEFAULT_CROP` es zoom 1 centrado). `cropRect(imageW, imageH, photoW, photoH, crop)` → `{ sx, sy, sw, sh }`: recorte cover dividido por el zoom, sin salir de la foto. `clampCrop`, `panCrop(…, crop, dx, dy)` (la foto sigue al puntero; `dx`/`dy` en fracciones del área en pantalla), `cropDpi` e `isLowResolution` (< 150 DPI).
- `src/sheetLayout.js`: hojas del PDF de cuadros, lógica pura. `FRAME_SHEETS` (`a4`, `a3`), margen 10 mm, 5 mm entre cuadros y `CUT_MARK` (de 1 a 2,2 mm por fuera de la esquina). `frameFits(size, sheetId)`. `packFrames(frames, sheetId)` acomoda en filas y en orden, prueba la hoja vertical y la horizontal y devuelve la de menos hojas (empate: vertical) como `{ orientation, sheets }`, con cada cuadro en `{ id, x, y, width, height, rotated }`; gira un cuadro solo si no entra derecho y devuelve `null` si alguno no entra. `fullSheetPages(frames)` (una hoja por cuadro, `{ id, orientation }` con la orientación del cuadro). `exportDpi(w, h)`: `EXPORT_DPI` (300) o el mayor entero que deja el canvas en `MAX_CANVAS_PIXELS` (16 Mpx, por Safari de iOS; un A3 queda en 287). `cutMarks(rect)` (8 líneas) y `framesFileName(sheetId)` (`cuadros.pdf` / `cuadros-a3.pdf`). Una hoja desconocida se trata como A4.
- `src/frameState.js`: estado en memoria de los cuadros, separado del comic (`images`, `size`, `customSize`, `mat`, `matColor`, `sheet`), sus mutaciones (`addFrameFiles`, `removeFrameImage`, `setFrameSize`, `setCustomFrameSize`, `setMat`, `setMatColor`, `setFrameSheet`, `toggleFrameOrientation`, `setFrameCrop`, `resetFrameCrop`) `currentFrameSize()` y `currentPdfSheet()` (la hoja de la medida si es de hoja completa, si no `sheet`: la hoja de la medida se calcula y no se guarda, así la elegida a mano se conserva). Cada foto guarda la `orientation` de su cuadro y su `crop`. `addFrameFiles` repite la carga del comic con sus mismos tipos y límite. Si la medida no entra en la hoja elegida, la hoja pasa a A3; `setFrameSheet('a4')` se ignora en ese caso. Con una medida de hoja completa no se fuerza la hoja y `setFrameSheet` se ignora. `setFrameSize('custom')` copia la medida elegida pasándola por `clampCustomSize` (desde A3 queda 27 × 40).
- `src/frameRender.js`: `frameFor(image, size, matId, matColor)` → `{ width, height, mat, matColor }` en mm, y `renderFrame(image, frame, canvas)`, que toma la escala del ancho del canvas, pinta el paspartú y dibuja el recorte de `cropRect` en el área de la foto.
- `src/frameUi.js`: `initFramesUI()`, DOM y eventos de `#frames-view`. Desplegables Medida (con Ancho/Alto en cm para "Personalizada", validados en `change`), Paspartú (el color va en un `<fieldset>` que se deshabilita con "Ninguno") y Hoja (A4 deshabilitada si la medida no entra; muestra `currentPdfSheet()` y se deshabilita con una medida de hoja completa, que además muestra `#frames-full-sheet-hint` con el aviso de imprimir sin bordes). `refresh()` actualiza los controles, el contador y el texto de hojas (una hoja por foto con hoja completa) y agenda las tarjetas (una vez por frame). Cada tarjeta (`createFrameCard()`) tiene el cuadro, la medida en texto, el aviso de baja resolución, Zoom, Girar, Centrar y Quitar. El arrastre y el zoom vienen de `cropControls.js`. El arrastre, el zoom y Centrar redibujan solo esa tarjeta; Girar y Quitar rearman toda la vista previa. "Descargar PDF" y "Hoja" se deshabilitan sin fotos y mientras se genera.
- `src/framePdf.js`: `exportFramesPdf(images, { size, mat, matColor, sheet, fullSheet })`. Con `fullSheet`, una hoja por cuadro (`fullSheetPages`), con la orientación del cuadro, el cuadro en `0,0` sin girar y sin marcas de corte. Si no, acomoda los cuadros con `packFrames`. En los dos casos dibuja cada uno a `exportDpi` con `renderFrame` (girado 90° en un segundo canvas si `rotated`), lo agrega como JPEG 0.92 a su medida exacta, sin `fullSheet` traza las marcas de corte (0,2 mm, `#999999`) y descarga con `framesFileName`.
- `src/cropControls.js`: controles de reencuadre de las tarjetas, compartidos por cuadros y stickers. `attachCropDrag(canvas, { image, area, outer, setCrop, onChange })` (arrastre con pointer events y `setPointerCapture`; `area` y `outer` en mm miden el desplazamiento en fracciones del área de la foto en pantalla), `createZoomControl({ image, area, setCrop, onChange })` → `{ element, sync }` (rango de 100 a 300 %; `sync()` lo usa "Centrar") y `makeCardButton(label, ariaLabel, onClick)`.
- `src/stickerSizes.js`: formas, tamaños, bordes y copias de los stickers, lógica pura, en mm. Cada forma de `STICKER_SHAPES` tiene `format` (`square`, `landscape` o `portrait`) y `corners` (`circle`, `straight` o `rounded`); son 7, en el orden del desplegable: `circle`, `square`, `rounded`, `landscape`, `landscape-rounded`, `portrait` y `portrait-rounded`. `RECT_RATIO` (2/3, lado corto / lado largo), `ROUNDED_RADIUS` (0,15 del lado corto), `STICKER_SIZES` (el lado del cuadrado o el lado largo del rectángulo: `3cm`, `4cm`, `5cm`, `7cm`, `10cm` y `custom`; claves no numéricas para que no se reordenen), `CUSTOM_STICKER_LIMITS` (20..190 mm), `STICKER_BORDERS` (`none`, `fino` 1,5, `ancho` 3), `DEFAULT_BORDER_COLOR` y `COPIES_LIMITS` (1..50). `resolveStickerSize`, `normalizeCustomStickerSize` (mm entero o `null`), `normalizeCopies` (ajusta a 1..50, `null` si no es un número), `stickerDimensions(shape, size)` → `{ width, height }` (el lado corto del rectángulo se redondea a 1 mm: 5 cm → 50 × 33), `shapeRadius(shape, width, height)` (sale del lado corto), `stickerFor(size, shape, border, borderColor)` → `{ width, height, shape, border, borderColor }`, `stickerPhotoArea(sticker)` (`{ x, y, width, height, radius }`: el radio interior es el exterior menos el borde), `expandCopies(images, width, height)` (lista para `packFrames`, cada foto repetida `copies` veces), `stickerText` ("Círculo de 5 cm", "Rectángulo horizontal de 5 × 3,3 cm") y `stickersFileName` (`stickers.pdf` / `stickers-a3.pdf`).
- `src/stickerState.js`: estado en memoria de los stickers, separado del comic y los cuadros (`images`, `size`, `customSize`, `shape`, `border`, `borderColor`, `sheet`), sus mutaciones (`addStickerFiles`, `removeStickerImage`, `setStickerSize`, `setCustomStickerSize`, `setStickerShape`, `setStickerBorder`, `setStickerBorderColor`, `setStickerSheet`, `setStickerCrop`, `resetStickerCrop`, `setStickerCopies`) y `currentStickerSize()`. Cada foto guarda su `crop` y sus `copies`. `addStickerFiles` repite la carga del comic con sus mismos tipos y límite. `setStickerSize('custom')` copia el tamaño que estaba elegido. La hoja nunca se fuerza: todos los tamaños entran en A4 (los rectángulos, derechos, así que `packFrames` nunca los gira).
- `src/stickerRender.js`: `renderSticker(image, sticker, canvas, { cutLine })` toma la escala del ancho del canvas (con la proporción del sticker), lo deja transparente fuera de la forma, pinta la forma con `borderColor`, recorta la foto a la forma interior y dibuja el recorte de `cropRect`. Con `cutLine` (vista previa) traza el contorno con 1 px `#999999`. Todas las formas usan el mismo trazado con `arcTo`, un rectángulo de `width` × `height` con esquinas de radio `radius` (en un cuadrado, radio = lado / 2 es el círculo).
- `src/stickerUi.js`: `initStickersUI()`, DOM y eventos de `#stickers-view`. Desplegables Forma, Tamaño (con "Tamaño (cm)" para "Personalizado", validado en `change`), Borde (el color va en un `<fieldset>` que se deshabilita con "Ninguno") y Hoja. `refresh()` actualiza los controles y los textos y agenda las tarjetas (una vez por frame); `updateCounts()` actualiza solo el contador ("N fotos · M stickers") y el texto de hojas, y lo usan "Copias" y "Hoja" para no rearmar las tarjetas. Cada tarjeta (`createStickerCard()`) tiene el sticker (canvas con el lado largo en `PREVIEW_SIDE` y el corto en proporción), su texto, el aviso de baja resolución, Zoom, Copias, Centrar y Quitar. "Descargar PDF" y "Hoja" se deshabilitan sin fotos y mientras se genera. Reusa clases CSS de los cuadros (`frames-custom-size`, `frames-mat-color`, `frames-preview`, `frame-card`); `.sticker-card canvas` usa `drop-shadow` para que la sombra siga la forma.
- `src/stickerPdf.js`: `exportStickersPdf(images, { size, shape, border, borderColor, sheet })`. Acomoda `expandCopies` con `packFrames`, dibuja cada foto una sola vez a `exportDpi(width, height)` con fondo blanco fuera de la forma, la pasa a jsPDF como bytes JPEG 0.92 con el id de la foto como alias (así se guarda una vez y las copias no vuelven a decodificarla), traza la línea de corte vectorial (`circle`, `roundedRect` o `rect`, 0,2 mm, `#999999`) y descarga con `stickersFileName`.
- `tests/`: tests de Vitest.

## Flujo de trabajo: desarrollo guiado por specs

El repo usa un flujo guiado por specs con dos skills del proyecto. Vienen de `Klerith/fernando-skills` y sus versiones están fijadas en `skills-lock.json`. `.claude/skills/*` son enlaces simbólicos a `.agents/skills/*`.

- `/spec <descripción de la funcionalidad en una oración>`: diseña una spec mediante preguntas aclaratorias y la guarda como `specs/NN-slug.md` con estado `Borrador`. No escribe código. La primera vez también crea `specs/.spec-config.yml` (`AutoCreateBranch: true`).
- `/spec-impl <NN-slug>`: implementa una spec solo si su estado significa "Aprobado". Solo la persona cambia el estado a Aprobado. La skill crea la rama `spec-NN-slug` o se cambia a ella. Implementa el plan paso a paso y se detiene después de cada paso para revisar el diff. Nunca hace commit por su cuenta.

Convenciones que aplican estas skills:

- Las specs siguen `.agents/skills/spec/template.md`. Empiezan con un encabezado (Estado / Depende de / Fecha / Objetivo en una oración). Después vienen Alcance (Dentro / Fuera), Modelo de datos, Plan de implementación, Criterios de aceptación y Decisiones. Riesgos es opcional. Cierran con una sección "Qué no incluye".
- Las specs se numeran en orden y con dos dígitos (`01-`, `02-`, …). Una spec nueva usa el mismo idioma y los mismos nombres de estado que las existentes. Estados en español: `Borrador`, `En revisión`, `Aprobado`, `Implementado`, `Obsoleto`.
- Durante la implementación, seguir la spec al pie de la letra. Ante pedidos fuera de alcance o ambigüedades, consultar al usuario en lugar de improvisar.
